# Руководство пользователя — «Мой второй мозг»

> Telegram-бот `@cyberdub_second_brain_bot`, работающий 24/7 на сервере 44.  
> Под капотом — Claude (подписка Max, модель Sonnet), Obsidian-vault с Syncthing-синхронизацией.

---

## Как это работает

Ты пишешь или говоришь в Telegram → бот передаёт сообщение живой Claude-сессии →
Claude отвечает и сохраняет запись в vault → vault синхронизируется в твой Obsidian.

```
Telegram → бот → tmux:claude → vault (/srv/data/second-brain/vault/)
                                    ↕ Syncthing
                              Obsidian на ноутбуке
```

---

## Что можно слать

| Тип | Что происходит |
|-----|----------------|
| 💬 Текст | Claude обрабатывает и отвечает; запись сохраняется в дневник дня |
| 🎤 Голосовое | Транскрибируется локальным Whisper → обрабатывается как текст |
| 📷 Фото | Принимается, фиксируется в дневник |
| ↩️ Пересланное | Принимается как есть |

## Команды

### Управление сессией

| Команда | Что делает |
|---------|-----------|
| `/start` | Приветствие + список команд |
| `/help` | Краткая справка |
| `/new` | Начать новый чат — сбросить контекст сессии |
| `/compact` | Сжать контекст текущей сессии (сохранить суть, освободить токены) |

### Данные и статус

| Команда | Что делает |
|---------|-----------|
| `/status` | Сводка сегодняшнего дня: сколько записей, голосовых, фото; статистика за 7 дней |
| `/process` | Запустить обработку записей дня прямо сейчас (без ожидания до 21:00) |

### Кнопки клавиатуры

| Кнопка | Аналог |
|--------|--------|
| 📊 Статус | `/status` |
| ⚙️ Обработать | `/process` |
| ❓ Помощь | `/help` |

## Автоматика

### Ночная обработка (21:00 МСК)

Каждый день в 21:00 бот запускает обработку накопленных за день записей.
Результат появляется в Obsidian в файле дневника (`vault/daily/YYYY-MM-DD.md`).

Чтобы запустить раньше — отправь `/process` или нажми ⚙️ Обработать.

### Утренний doctor (08:00 МСК)

Каждое утро бот делает self-check и присылает статус:
- 🟢 — всё работает
- 🔴 — есть проблема (Claude-сессия упала, Whisper не отвечает и т.п.)

## Vault — где хранятся записи

После синхронизации в Obsidian видишь:

```
vault/
  daily/
    2026-06-16.md    ← дневник сегодня
    2026-06-15.md    ← ...
  thoughts/          ← отдельные мысли, захваченные ботом
  attachments/       ← медиафайлы
```

Файл дневника имеет структуру:

```markdown
# 2026-06-16

## 14:30 [voice] Голосовое 40с
Транскрипт + обработка Claude

## 15:12 [text]
Текст сообщения + ответ Claude

## 21:00 [process] Итоги дня
Автоматическая сводка событий
```

## Частые вопросы

**Бот не отвечает — что делать?**

Обычно это временная нагрузка. Подожди 10–15 секунд и повтори.
Если «❌ Ошибка сессии» — Claude-сессия зависла; она автоматически восстановится
через watchdog в течение 1–2 минут. Можно написать что угодно, чтобы проверить.

**Можно ли слать несколько сообщений подряд?**

Да, но они обрабатываются последовательно — каждое ждёт ответа на предыдущее.

**Голосовое не транскрибируется / пустой ответ**

Проверь, что голосовое не пустое. Сервер Whisper (faster-whisper-large-v3)
запускается отдельно на .44 — если он упал, бот ответит ошибкой транскрипции.

**Как посмотреть историю за день?**

Открой Obsidian → `vault/daily/YYYY-MM-DD.md`, или отправь `/status`.

**Как начать новую тему, не засоряя контекст?**

Отправь `/new` — контекст сессии сбросится, vault остаётся нетронутым.

**Хочу сжать память, но не терять суть**

Отправь `/compact` — Claude резюмирует текущий контекст и сжимает его.

## Управление для администратора (сервер 44)

```bash
# Статус всех сервисов
dbrain status

# Логи в реальном времени
dbrain logs

# Заглянуть в живую Claude-сессию (не вводить ничего вручную!)
dbrain attach
# Выйти: Ctrl+B, затем D

# Принудительный self-diagnostic
dbrain doctor

# Перезапуск бота (мозг НЕ трогается)
systemctl --user restart dbrain-bot.service

# Перезапуск с полным сбросом Claude-сессии
tmux kill-session -t "$(cat ~/.dbrain/brain.name)"
systemctl --user restart dbrain-bot.service
```

**Важно:** `dbrain attach` только смотреть. Любой ввод вручную в tmux-панели
нарушит протокол `<<<R:rid>>>`/`<<<E:rid>>>` и следующий запрос бота зависнет.
